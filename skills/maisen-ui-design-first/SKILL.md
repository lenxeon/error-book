# 麦森错题本 UI 设计先行

收到新页面、页面改版或 UI 视觉请求时，按以下顺序工作。用户说“设计页面”时，交付物是设计稿，不是源码。

## 1. 讨论需求

- 了解页面目标、使用者、入口与返回路径、主要内容和操作、需要的数据及页面状态。
- 参考首页和用户提供的设计稿，延续柔和、温暖、儿童友好的视觉风格。避免擅自加入强高光、塑料质感、整页背景图或未经确认的页面内容。
- 对影响页面结构或使用方式的未知事项向用户简短确认；对可合理推断的细节先提出建议。
- 本阶段整理需求和页面结构，不改应用源码。

## 2. 交付页面设计稿

- 按目标手机尺寸绘制完整页面，包含导航、内容层级、重点操作和关键状态；多页需求逐页呈现。
- 使用准确中文文案，标出动态数据、点击后的行为和空状态。设计应与首页的色彩、圆角、插画和留白保持一致。
- 将可查看的设计图交给用户审阅，根据反馈迭代；用户确认设计稿后，才进入素材和代码阶段。
- 不把整页设计图或素材图集直接作为应用页面背景。

## 3. 制作独立 UI 小图

- 先列出确认稿中确实需要的头像、吉祥物、背景或功能插画；优先复用已有资源。为每张图说明用途、比例和建议尺寸。
- 用图像生成工具制作缺少的位图素材，逐张检查主题、裁切和清晰度。文字、按钮、标签和实时数据由 UI 组件绘制，不烘焙进插画。
- 横幅和长图保留矩形源图，圆角由 React Native 样式处理。需要透明背景的独立元素使用透明图；不同用途的素材分别导出、命名和引用，不整图引用图集。
- 用户审阅素材后，再进入代码实现；若页面无需新插画，复用现有素材并说明即可。

## 4. 按确认稿还原代码

- 仅在设计稿与所需素材确认后改 React Native 源码。
- 还原确认稿中的布局、文案、字体层级、间距、颜色、圆角、素材裁切、导航和交互状态；动态内容保持为原生文本与组件。
- 检查 iOS 和 Android 的安全区、滚动、触控尺寸、系统字体缩放和返回行为。按目标尺寸实际预览，逐项对照设计稿修正；编译成功不能替代视觉核对。
- 报告实现和验证结果，并链接设计稿和素材。

## 阶段边界

- 用户要求设计时，先交付设计稿，不擅自改产品代码。
- 用户要求实现但本轮设计稿尚未确认时，先补齐需求和设计稿阶段；不跳过用户定义的顺序。
- 保护已有页面、素材和其他会话的改动。设计稿、独立图像资源与应用源码分开存放。
